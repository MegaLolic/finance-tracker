# Финанс · веб-интерфейс

Адаптивный интерфейс на React, TypeScript и Vite. Графики строятся через Recharts.
Запросы идут на `/api/**`: сервер интерфейса перенаправляет их в API Gateway,
сохраняя один origin для браузера. Изменять CORS в Java-сервисах не требуется.

## Разработка

Нужен Node.js 22.12+ либо 24 и запущенный backend проекта с gateway на порту 9000.
Из каталога `frontend`:

```powershell
npm install
npm run dev
```

Открыть `http://localhost:5173`. Другой gateway можно задать перед запуском:

```powershell
$env:GATEWAY_URL = 'http://127.0.0.1:9000'
npm run dev
```

## Сборка и запуск

```powershell
npm test
npm run build
npm start
```

Собранный интерфейс доступен на `http://localhost:4173`. `npm start` использует
`server.mjs`: он раздаёт `dist` и проксирует API без дополнительных зависимостей.
Переменные окружения: `PORT` (4173), `HOST` (0.0.0.0), `GATEWAY_URL`
(`http://127.0.0.1:9000`). `npm run preview` служит только для локального просмотра
сборки Vite. Для внешнего доступа нужен HTTPS reverse proxy перед сервером.

## Телефон и Android

Телефон и компьютер должны быть в одной Wi-Fi сети. Открой на телефоне
`http://<локальный-IP-компьютера>:5173` при `npm run dev` либо порт 4173 при
`npm start`. Доступ к порту должен разрешать брандмауэр Windows; адрес gateway
остаётся серверным, телефон к порту 9000 напрямую не обращается.

Manifest, PNG-иконки и service worker включены в сборку. Для установки на
настоящем Android через «Установить приложение» или «Добавить на главный экран»
нужен HTTPS. Исключение для `localhost` относится к самому устройству и не делает
HTTP-адрес компьютера в Wi-Fi безопасным контекстом. Поддержка установки зависит
от браузера. Данные API и токены service worker не кеширует; при отсутствии сети
финансовые операции недоступны.

## Особенности данных

- Пользователь определяется backend по access JWT. Пара токенов хранится в
  `sessionStorage` текущей вкладки; пароль не сохраняется.
- Отчёты относятся к выбранному счёту. Валюты разных счетов не суммируются и не
  конвертируются.
- Дата новой операции задаётся сервером. Backend пока не поддерживает ввод
  операций задним числом.
- Аналитика получает изменения через Kafka. После записи операции обновление
  отчёта может занять некоторое время.
- Обновление/удаление счетов и операций использует версии backend. При конфликте
  нужно обновить данные и повторить действие с актуальной записью.
- После неопределённой сетевой ошибки денежный POST не повторяется автоматически:
  сначала проверь список операций, чтобы исключить двойную запись.

Кнопка «Посмотреть демо» открывает отдельный локальный пример с заполненными
графиками. Его изменения остаются только в памяти и не отправляются в backend.
Демоданные сбрасываются после выхода или перезагрузки; демонстрационных аккаунтов
в базе и публичного развёртывания нет.

## Проверки интерфейса

`npm test` проверяет календарные границы, суммы и поведение API-клиента.
`npm run test:e2e` собирает интерфейс и проверяет demo/реальный backend в desktop
и Android-эмуляции Playwright. На Windows используется установленный Edge;
на Linux предварительно установи Chromium командой `npx playwright install chromium`.
Backend должен работать. Сценарии создают отдельных тестовых пользователей и
запрашивают их удаление в конце. Настоящий Android дополнительно стоит проверить
на устройстве; эмуляция не проверяет установку PWA и системный браузер телефона.

Для фонового запуска на Windows из корня проекта: `./scripts/frontend.ps1 start`.
Остановка: `./scripts/frontend.ps1 stop`. Если Node.js не находится через PATH,
передай `-NodePath 'D:/NodeJs/node.exe'` с путём к установленному Node.
Скрипт сохраняет PID/время запуска и останавливает только созданный им процесс.
